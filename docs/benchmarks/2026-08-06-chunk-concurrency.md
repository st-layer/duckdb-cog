## 무엇이 바뀌었나

행 단위 순차 `block_on` → 청크 단위 3단계: 동기 파싱 → 유일 경로 동시
open → 행별 zonal `stream::buffered(cap)` (순서 보존, 최소 행 에러 결정성,
NULL 행 자리 유지). 네트워크는 tokio IO 런타임에서 겹치고 decode 는 종전대로
호출 스레드. `COG_FETCH_CONCURRENCY` 기본 16, 1 = 순차 폴백.

## 남은 상한 (후속 후보)

- **decode 직렬화**: 22 타일 decode 가 호출 스레드에서 순차 (~2s 추정) —
  threading 모델 변경(워커 분산)은 별도 논의.
- **단일 링크 대역폭**: 22 read ≈ 15MB 전송이 링크 총 대역폭에 지배됨 —
  동시화로 스트림당 1.3MB/s 제약은 우회했지만 물리 링크가 다음 바닥.
- 씬 수가 cap(16)을 넘으면 웨이브 발생 — 대형 시계열은 cap 상향 여지.
