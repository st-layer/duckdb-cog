## 결과

| 구성 | cold (200필지) | warm (200필지) | ms/필지 (warm) |
| -- | -- | -- | -- |
| `COG_TILE_CACHE_MB=0` (캐시 끔 = 종전 동작) | 303.9 ms | 172.8 ms | 0.86 |
| `COG_TILE_CACHE_MB=256` (기본) | **129.7 ms** | **17.1 ms** | **0.09** |

- **warm 10.1× / cold 2.3×** — localhost 라 fetch 1회가 μs 수준인데도 이 격차다.
  개선분의 본질은 **fetch·decode 횟수**: 캐시 끔은 필지마다 타일 재fetch+재decode
  (200콜 = 타일 접근 200회), 캐시 켬은 콜드 패스에서 타일 4개를 각 1회만 가져오고
  warm 패스는 **fetch 0** (엔진 계약 테스트 `tile_cache.rs` 가 횟수를 직접 검증).
- 캐시 끔의 warm 이 cold 보다 빠른 것(303.9→172.8)은 OS 페이지 캐시·연결 재사용
  몫이며, 두 패스 비용이 같은 자릿수라는 점 자체가 리포트가 지적한
  "동일 쿼리 재실행이 같은 비용(48.8s→46.7s)" 병리의 재현이다.

## 실 워크로드 환산 (리포트 수치와 대조)

리포트(2,511필지 × 4콜 = 526s/씬)의 병목은 같은 타일 ~168회 재다운로드 — 실 S3
왕복(수십~수백 ms)이 곱해지는 항이다. 본 실측은 그 곱해지는 **횟수가 N필지 → 타일
수로 떨어짐**을 계약 테스트와 벤치 양쪽에서 확인한 것이고, 실 네트워크에서의
기대 효과(fetch 4,527→~27회, 526s→~10s/씬)는 횟수 감소비가 그대로 지배한다.
localhost 수치는 하한 — 원격 지연이 클수록 격차는 커진다.

## 계약 (엔진 테스트 `crates/engine/tests/tile_cache.rs`, 6본)

1. 같은 zonal 재호출 → 추가 fetch 0, 값 비트 동일
2. 한 타일 안 N개 필지 → 타일 fetch 총 1회 (168× → 1×)
3. 캐시 미부착 리더(로컬 경로 상당)는 현행 그대로 (호출마다 fetch)
4. 예산 초과 타일은 상주 불가 → 재fetch (동작은 옳음)
5. 리더 격리: 같은 캐시라도 ReaderId 다르면 교차 서빙 금지 (재열림 = 무효화)
6. 콜드 타일에 8스레드 동시 진입 → fetch 1회 (single-flight)

값 불변의 상위 감시는 기존 rasterio 오라클 (`just check` 전체 그린, 무변경 통과).

## 설정

- `COG_TILE_CACHE_MB` — decoded 타일 LRU 의 바이트 상한 (기본 256, `0` 비활성).
  프로세스 전역 단일 예산이라 리더 수와 무관하게 상주 메모리가 이 값을 넘지 않는다.
- 타일 수명 ≤ 리더 수명: 리더 캐시 TTL(`COG_REMOTE_CACHE_TTL_S`, 기본 60s)이
  타일 무효화를 겸한다 — TTL 안에 원본이 바뀌면 낡은 픽셀을 읽는다 (README 명시).
- 로컬 경로는 캐시하지 않는다 (현행 유지).
